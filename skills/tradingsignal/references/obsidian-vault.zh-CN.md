# 把分析写进 Obsidian

用户要把这次分析存下来以后复盘，或者要回看以前的判断时，用这个流程。**默认不开**：没有明确同意就不往磁盘写任何东西。

## 写之前先问

1. 分析结束时问一次要不要记进 Obsidian。同一段对话里被拒绝过就不要再问。
2. 同意后再问 **vault 路径**。不要猜，不要写进用户没有指名的 vault，也不要把新 vault 建在另一个 vault 的根目录里——嵌套的 vault 会被索引两次，两边的笔记会互相串。
3. 检查路径存在，并且有 `分析/`、`标的/`、`附件/`。没有就先列出准备创建的目录，得到同意再建。往已有 vault 写之前，先核对结构没有漂移——尤其是标的页 Dataview 查询用到的每个列名，都必须是分析模板里真实存在的 frontmatter 字段：漂移的症状是一列空白，看起来和「还没有分析」一模一样（本仓库 `scripts/vault_check.py` 是参考检查）。
4. 只写这三个目录里面，任何时候都不写到外面。

换一段新对话后路径不会自动记得。除非用户自己存了，否则要请他再给一次，不要编一个“记得的”路径。

## 两层，因为一层答不了两个问题

- `标的/<SYMBOL>.md`：一个标的一篇，写**现在**怎么看、哪些价位仍然有效，看法变了就改。
- `分析/<日期>-<SYMBOL>-<周期>-<id>.md`：一次分析一篇，写**当天**怎么看。写完不改，只在复盘时补复盘那一节。

只有一层就会丢掉「我现在怎么看」和「我当时怎么看」中的一个。复盘两个都要。

## 写入流程——每次都一样

第一次经聊天客户端的真实运行同时漂移了四处（自造文件名、自造标签、没建标的页、正文嵌入实时图），
所以流程编号固定，任何一步都不可省略、不可换序：

1. **先定身份。** `analysis_id` = 6 位小写十六进制，本篇固定。文件名 =
   `YYYY-MM-DD-<SYMBOL>-<周期>-<id>.md`：`<SYMBOL>` 去掉 `=X` 后只留字母数字
   （`BTC/USDT` → `BTCUSDT`）；`<周期>` 是**决策周期**——多周期研究仍然只在一个周期上做决定，
   那个周期进文件名和 `timeframe` 字段；正文引用的其他周期写进 `context_timeframes`，
   这也是允许链接指向它们的依据。「多周期」不是周期，
   没法排序也没法筛选。
2. **frontmatter 从 `_模板/分析.md` 整套照抄**——每个键都要，不加新键、不改名。
   字段值用 vault 自己的词表，不要换一种语言自造。
3. **标签只用 `标签.md` 里的。** 词表缺就提议加进词表，绝不在笔记里现造。
4. **标的页每次都要 upsert。** `标的/<hub>.md`：`<hub>` 是 symbol 去掉 `=X`、`/` 换 `-`。
   没有就按 `_模板/标的.md` 建，带上推导出的事实标签；有就直接用。两种情况都要在
   `## 历史分析` 下加一条普通 Markdown 链接指向新分析，并更新 `现在的看法`、
   `current_bias` 和 `updated`。upsert 必须**幂等**：链接已存在就不再加，
   同一篇重复保存后标的页只有一条链接，不是两条。没有标的页的分析只回答「我当时怎么看」，「我现在怎么看」就悄悄无处安放——
   第一次真实运行漏掉的正是这一步。
5. **图：vault 笔记要把图贴出来。** 这个界面和聊天回复恰好相反，两者不能混。
   Obsidian 能渲染本地图片，所以归档图要用 `![[附件/...]]` **嵌在正文里**、
   放在它支撑的那条理由下面，图下再附一条可读文字链接指向该标的/周期/方法的最新分析。
   **一篇分析可以有多张图**——跑了几个方法就放几张——**每张图放在它对应的那一节里**：
   VCP 的图放在 VCP 那段下面，TD9 的图放在 TD9 那段下面。**不要都堆到末尾的 `## 链接` 里**；
   那一节是放链接的，图堆在那里就没有人会在它证明的那句话旁边看到它。
   **图上方最近的那个 `## ` 标题必须点出这张图的方法名**（中英文均可）——
   `## VCP 形态`、`## TD9 序列`、`## DeMark 计数`、`## 趋势`、`## 指标`。
   不点方法的标题（`## 结论`、`## 总结`）不是图的位置，完全没有标题也不是；
   checker 两种都判红。旧规则只禁止 `## 链接`，结果 TD9 的图只要避开 `## VCP`
   就能放在任何地方。
   证据只剩一串 URL 的笔记，一眼看不出任何东西——而这正是 vault 存在的理由。
   **归档是必须项，不是可选项**：用户要求写入的一次保存，至少欠一张真实分析图——
   归档、hash 校验、嵌入正文、图的紧邻下方配方法链接。每张图的链接必须匹配**这张图**：
   slot 对应的方法，以及图注写明周期时的那个周期。**4h 的图不能配 1d 的链接。**
   slot 就是方法名，取自闭集——`levels, vcp, chan, td9, wyckoff, fib, trend, indicators`——
   文件名是 `附件/<id>-<slot>.png`。闭集之外的 slot（`main` 或任何新名字）不隐含方法，
   必须在 frontmatter 用 `primary_method: <tab>` 显式绑定；**没绑定就判失败**，
   而不是任何 tab 都放行。
   证据链确实闭不上时（实时图画出了比 `as_of` 更晚的 K 线、或没有已登录浏览器），
   笔记照写，带「未归档」标记说明缺什么，但那是**降级记录**，必须报「**未完整保存**」。
   不要告诉用户分析已进 Obsidian；告诉他缺什么、补什么才算完整。
   实时图 URL 仍然写进 `## 链接` 的 `liveUrl` 行，因为它打开的是**今天**的数据，不是冻结证据。
6. **收尾跑 postcondition，修完才算写完。** 一次保存的产物必须同时存在且一致：
   分析 frontmatter、标的页、标的页指回本篇的链接，以及图片合同**生效的那一侧**——
   `image_archived: true` 时每个声明的附件都存在且 SHA-256 相符；`false` 时不欠附件，
   但正文必须用「**未归档**」明说缺口，不能靠暗示。同一篇里章节标题不得重复。
   **运行随本 skill 打包的 checker**——skill 目录内的 `scripts/vault_check.py`：
   `python3 <skill目录>/scripts/vault_check.py <vault路径>`。不要临时拼替代检查——
   第一次 Codex 运行就是这么做的，自称 PASS，漏掉了一条真 checker 会拒绝的猜测链接。
   任何一样不成立就明确报「**未完整保存**」并说明缺哪样——
   绝不能在只写了一半时告诉用户分析已进 Obsidian。

## `方法/`——方法论，与写它的那个版本绑定

`方法/<TOPIC>.md` 镜像**已安装版本**；`方法/历史/<TOPIC>-<版本>.md` 保存**已被替换掉的**旧定义，
这样一篇 `skill_version: 0.1.12` 的分析，仍然能对照那个版本当时说的 "VCP" 来复盘。
两半都要：没有镜像，vault 会落后；没有历史，一次升级就把所有旧分析引用的定义悄悄改写了。

**不要手工做这件事。** skill 里带了两个脚本：

```
python3 <skill目录>/scripts/sync_methodology.py <vault> --needed <版本>
```

打印出缺失或过期的 topic。**只对这些** 调用 `get_methodology(topic=…)`，把返回内容**原样**
写进一个按 topic 为键的 JSON，然后：

```
python3 <skill目录>/scripts/sync_methodology.py <vault> <版本> fetched.json
```

判断全部由脚本做：定义没变就只升版本号、不留快照——每个版本都留一份相同内容的快照，
会把 vault 塞满相同文件，反而让「方法论到底改没改」看不出来；定义变了就先把旧的按它所属的
版本存进历史再替换，且**快照写入后不再改写**。

**原样存工具返回的内容**。不要改写、不要摘要、不要"优化措辞"：分析引用这些笔记作为
它当时用的定义，定义被改过，所有引用它的分析就都变成假的。

检查器随 skill 一起打包、能读到自己的版本号，所以「方法论是不是最新的」不需要联网就能判定。

## frontmatter 写什么

结构化字段是复盘查询的依据，所以只放事实，不放文章：

```yaml
analysis_id, symbol, asset_class, market, timeframe
as_of          # 这篇针对的最后一根「已收」K 线
date           # 写这篇的日期
provider, route, data_digest    # 这篇依据的是哪份数据
methods, bias, confidence, key_levels, invalidation
outcome        # 先留空，复盘时才填
image_archived, image_sha256
data_staleness_days             # 序列落后时，as_of 与今天的差
```

「算不出来」和「中性」在这里也要分清，和聊天里的回答一样严格：留空是诚实的，填 0 是一个判断。

## 标签是受控词表

读 vault 自己的 `标签.md`，只用里面列的标签。自由发挥的标签一年后等于没有：同一件事五种写法，筛不出完整结果。

- **事实标签**（市场、地区、数据源）由你从标的推导，不手写——推导出来的标签不会漏也不会拼错。
- **判断标签**（方向、方法、结果）来自分析本身，其中 `结果/*` 只在复盘时才填。
- 两类不要混。「所有美股」是事实，「所有我看多的」是判断，放进同一层两边都筛不干净。

需要词表里没有的标签时，提议加进 `标签.md`，不要在笔记里临时造一个。

## 图

**两个界面，规则相反。** 在**聊天回复**里（Codex、Claude）图渲染不出来，所以图表用具名文字链接传递，
绝不嵌入；在 **Obsidian 笔记**里图能渲染，所以归档图要嵌进正文，并在图下附文字链接。
把聊天规则套到笔记上会得到一堵 URL 墙，把笔记规则套到聊天上会得到一排坏占位框。**每次按界面判断。**

归档这次分析真正依据的那张图：用产品自己的「截图」动作，在已登录的浏览器里打开对应标的与周期。存成 `附件/<analysis_id>-<slot>.png`，用 `![[附件/...]]` 嵌入，并记下 SHA-256。
**正文嵌入的每一张图都必须在 `image_sha256s` 里按 slot 声明**——声明才是把这串字节绑到本篇的东西，
没人声明过的嵌图就是一张来路不明的图，判红。而且必须是本篇自己的文件：
文件名以本篇 `analysis_id` 开头，不能借用别篇的图。

每张归档图下方放一条可读文字链接，指向产品里**同标的/同周期/同方法的最新分析**——
`[查看 ETH/USDT 的最新 VCP 分析](...)`——让冻结的记录和活的视图一键互达。这是方法页 URL，
不是图表 URL；契约**已上线且精确**：
`https://tradingsignal.pro/app?market=<市场>&symbol=<URL编码的symbol>&timeframe=<周期>&tab=<tab>`，
`tab` 取 `indicators, levels, trend, fib, chan, td9, vcp, wyckoff` 之一，由方法决定
（VCP → `vcp`、TD/DeMark → `td9`、缠论 → `chan`、威科夫 → `wyckoff`、支撑阻力 → `levels`）。
缺 market、symbol、timeframe、tab 任何一项的链接不是深链，是猜测。**参数齐全但指错更糟**：checker 还要求链接打开的就是本篇的标的——同 symbol、同 market、周期是本篇决策周期或 frontmatter 里 `context_timeframes` 声明过的背景周期——并且 tab 必须与链接文字承诺的方法一致、且是本篇真正跑过的方法。一条能通过形状检查、却把读者带到另一张图的链接，正是这套检查要防的。

**图上画的东西如果超出笔记的说法，就不要归档。** 实时图里画出比 `as_of` 更晚的 K 线（正在形成的那根，或者序列已经刷新过），这张图就在「本篇证据」这个位置上和笔记自相矛盾。说明情况，把图留空。

要讲清楚一张图能证明什么：只有图上写了标的与周期，图才自证这两项；日期它证明不了——日期靠 `data_digest`、靠归档时库里没有更晚的 bar、靠文件名与 `analysis_id` 对应，三者合起来。把这条链写出来，不要让 PNG 顶替它。

## 链接

- `liveUrl`：可分享的图表链接。点开看到的是**今天**的数据，不是写分析那天的，标注必须这么写。不要说它能回到当天的图。
- `snapshotUrl`：能复现当天的链接。产品还没有之前，写「暂无」。

## 复盘

复盘要读 vault，而不是凭印象重推：

1. 按标签和 frontmatter 查 `分析/`，对准用户问的问题（「我看多过、后来没兑现的」「所有用斐波那契、且回撤到 0.618 的」）。每个标的页都要保留普通 Markdown 的历史链接——Dataview 是可选增强，没装插件的 vault 也必须能看到历史。
2. 每一条都取 `as_of` **之后**的走势，拿它和这篇自己写的 `invalidation` 比，而不是和事后挑的目标比。
3. 填这篇的 `outcome` 和复盘一节，补 `结果/*` 标签。原来的结论和依据不要动：为了对上结果而改过的记录，之后就没法再复盘了。
4. 报跨多篇的规律，不只报最后一篇；样本不够支撑结论时直说。
