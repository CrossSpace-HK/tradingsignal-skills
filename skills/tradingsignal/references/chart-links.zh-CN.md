# 附图的规矩

**要在回答里放图之前先读这一份。** 这里是机制：链接怎么写、哪个 URL 是哪个、
该要哪个预设。规则本身有约束力；它们背后的理由在
[输出契约](output-contract.zh-CN.md)。

它单独成文，是因为一个从头到尾不附图的会话不该为它付 token。

- 图一律写成 markdown 链接，链接文字要写明标的、周期、方法——
  `[查看 ETH/USDT 4小时 TD9 图](url)`。不许裸 URL，不许内嵌图片（`![](...)`）：
  聊天客户端不保证会取远程图片，坏掉的占位符正好落在"这里是证据"的位置上。
- **图链接 ≠ 方法页链接。** 图是一张图，方法页是实时交互分析。方法页链接绝不能自己拼——
  用工具返回的 `openIn`，它带着分析当时那一根 K 线和快照。手工拼的 URL 丢掉快照，
  读者看到的是实时价格，而旁边那句话说的是另一个时刻。
- 任何返回图的工具都要传 `conclusion`（`get_indicators`、`get_method_analysis`、
  `get_chart`、`get_levels`）：一句话，≤80 字，**是你的判断**，不是引擎读数。
- 图片会自己标注，历史变了它自己会写出来。不要把这行标注复述成"我核对过"，
  也不要说这张图和分析的其他输入一致——校验只覆盖该标的在该周期上的这条 K 线序列。
- 优先用 `get_method_analysis` 返回的图；否则用 `get_chart` 加对应预设
  （`price`、`chan`、`td9`、`wyckoff`、`vcp`、`levels`、`signals`、`trend`）。
  图只是背景而非证据本身时要说明。
- 每一条 bullet 都配能证明它的那张图；没有就说没有，绝不拿别的模块的图来凑——
  一张不显示所声称内容的图，比没有图更糟。
- 风险那一条的图必须是 `get_levels` 的图，且只能引用 `drawnLevels` 里的价格：
  那个字段列出的正是所附图上画了什么，不在里面的价格无法和图对照。
