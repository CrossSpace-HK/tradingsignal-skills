# Platform research — candidate integration

Use `get_research_report` only when listed by the connected server. Without IDs, list public reports; optional `symbol` and `cursor` filter/page. Pin the returned `reportId` for the full report and frozen chart URLs. Use `skillId` for one baseline method instruction. IDs are ts-trend, ts-levels, ts-td9, ts-chan, ts-vcp, ts-wyckoff, ts-fibonacci, ts-synthesis.

The adjacent `technical-methods/skillBundle.json` and eight source instructions are byte-identical to the platform baseline artifact. Load only the method relevant to the request. A later optimized report names a different release/digest; do not call its instructions the bundled baseline. The public report supplies method evidence and input hashes; current `get_indicators`/chart tools cannot recreate a historical frozen report.

State the report cutoff and publication time separately. Keep provider, basis, historical revision unknowns and applicability limits. Use existing evidence IDs; chart URLs are frozen report assets. Reported directional observations exclude fees/fills/portfolio sizing and are not a promise of success. Admin preview, scheduling, publication and optimization permissions are absent from this read-only workflow.

If the tool is unavailable or there is no published report, say so; do not claim the new backend is deployed or silently substitute a latest-data analysis. A separate current-market request may use the existing symbol-analysis workflow with its own stated time.

This branch is a development candidate. No plugin upgrade or backend release is implied by these files.
