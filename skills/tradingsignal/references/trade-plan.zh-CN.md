# 条件式交易计划

用于已经通过筛选的标的，或用户直接要求为指定标的制定计划的情况。

## 用证据建立计划

使用颗粒化方法结果和 `get_levels` 选择最近且可辩护的：入场区或突破触发、确认条件、失效位或止损、第一和第二目标、预估风险收益比、以及计划过期条件。

高周期定义市场状态和主要失效位，低周期优化时机。数据过期、方法明显冲突、失效位不清晰，或到下一支撑阻力的收益空间不足时，拒绝该机会。

不得把条件式机会说成无条件预测。说明入场前必须发生什么、什么会证明逻辑错误。用户没有提供组合规模和风险预算时不得给仓位大小。

## 输出结构

**用 SKILL.md 里的报告结构，不要在这里另立一套。** 之前这份文件和 SKILL.md
说的不一样，模型两个都没照做，自己生成了第三种（一张按周期分行的表格）。

先用一句话给出动作：回调进、突破进、观察、减仓或离场、回避。然后是**恰好四个
bullet**，每条最多两句，**每条紧跟它自己的图**：

1. **入场点**——具体价位区间，或者什么条件成立才进。
2. **计划出场**——目标位，以及一旦到了就说明想法错了的失效位。
3. **它现在在哪**——VCP 第几阶段、缠论什么位置，或哪几个互相独立的方法同时支持；
   并说明每个周期各自贡献了什么。
4. **风险**——上下各有多少空间，取自 `get_levels` 的 `riskReward`。
   **绝不给胜率或置信度**；当 `riskReward` 两侧返回 null 时，说关键位太近、没法衡量。

只有用户明确要 JSON 时才输出 JSON。默认就是这四条，因为看报告的是人。

若图表生成失败，保留结构化事实，但动作上限为 `WATCH`，并披露缺少视觉验证。
