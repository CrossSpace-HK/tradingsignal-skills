# 单标的分析

用于用户指定标的、周期或技术方法，并希望得到解释而不是全市场扫描的情况。

## 限定问题

支持范围不确定时调用 `describe_capabilities`。识别用户的持有周期，并为每个分析周期分配明确角色。用户只问一种方法时，不要为了制造共振而调用无关引擎。

只有用户明确需要快速概览时才用 `analyze_symbol`。深度研究应独立调用颗粒化模块：VCP 看阶段、趋势模板、收缩质量、枢轴和止损；缠论看笔、中枢、结构点、确认和失效；威科夫看区间质量、阶段、事件、入场、止损和目标；TD9 看 setup/countdown 成熟度、TDST、风险线和下一根确认；`get_levels` 看支撑阻力、聚类和距离；必要时才用 `get_candles` 或 `run_engine` 补充原始证据。

**研究单只标的时，趋势强度和指标共振是必做项，不是可选项。** 用 `get_indicators` 取：
它按六大类（趋势／动量／波动／量能／形态／支撑阻力）给出各有几个看多几个看空，
以及**具体是哪些指标在表态和它们各自的理由**。`side: "decisive"` 只留真正表态的那些，
这通常就是用户想问的——不是"全部指标怎么说"，而是"现在到底有哪几个在表态"。

**威科夫没有明显结论时就不要写。** 引擎自己声明：多空侧只由横盘前那一段的方向决定，
**无法区分派发与上涨中继的再吸筹**；`tr.quality < 0.5` 也不算可交易。
这两种情况下写一段威科夫，读者会把一个默认值读成一个判断。省掉它不会让分析变弱。

不能把一体化概览或同一引擎的两个结果当成独立证据。保留所有注意事项，并区分无法计算和中性读数。

## 解释结果

**第一句就给观点**（买入／卖出／中性），**紧接着一句趋势强度与指标共振**——
这两样是"为什么是这个观点"最快的回答，不要留到最后。然后再说明：

1. 高周期市场状态；
2. 当前结构与触发状态；
3. 最近的支撑、阻力和候选失效位；
4. 独立方法之间的一致与冲突；
5. 下一根 K 线或价格事件如何确认或否定当前判断。

每个方法自己的同标的、同周期图紧跟其理由。无法从图上确认关键方法时应说明，结论不得高于 `WATCH`。
